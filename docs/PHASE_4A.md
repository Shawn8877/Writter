# Phase 4A — Long Novel Stress Test（50章验收完成）

基线：`b8c30db`。本阶段先实测再优化，保留所有测试数据和失败记录，不部署、不增加模型、会员、支付或公开注册。

## 方法与预先约定

- 独立小说 `Long Novel Stress Test · 二十四小时之外`，description 与 Bible metadata 标记 `stress_test`。7名主要人物、12条 Golden Facts、3短/3中/2长期伏笔；100章人工规划大纲，3000字目标，正文全部真实 DeepSeek。
- `scripts/testing/long-novel-plan.mjs` 只提供作者正常可填写的设定与大纲；Golden Facts 只存于 Bible，不给产品添加测试小说分支，不用 Fixture 替代正文、记忆或审核。
- `long-novel-stress.mjs` 使用普通测试账号的 Supabase 会话及现有产品 Generation Run / Context / Writer / Memory / Review 服务与 RPC。Context 包装器仅计时和记录，不改变输入。主测试为服务层真实集成，另行浏览器验收，不把 CLI 运行冒充浏览器运行。
- 分阶段10、25、50、100章。每个检查点默认不批准下一阶段；每个 Critical 或失败步骤立即停止，独立阅读证据后记录继续或修复决定。所有已生成正文及旧报告保留。
- 进入下一阶段须无未解决的基础设施阻塞、资料错误写入或重复章节。进入100章还须50章全链路完成、无未解决重大 Golden Fact 违规或系统性 Memory 污染；Context不超过原180KB限制且最近区间输入用量趋稳，评分下降及反复严重问题有解释；RLS和数据库性能复核通过。不得以总体均分掩盖后段退化。
- 不提高产品每小时36次连续创作限额、不清除额度日志；遇限额等待恢复，记录其对吞吐的影响。失败只按现有恢复路径重试，不循环重写成功章节。
