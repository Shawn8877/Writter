# Phase 3D：AI 小说总编与章节质量控制

## 作者流程

AI 正文保存 → Memory 更新 → AI 编辑审核 → 保存报告。审核只解释问题、引用证据、提出建议，不修改正文、人物、世界、Bible 或 Memory。章节编辑器展示总分、状态、13 项指标、问题和建议；支持按 Critical / High / Medium / Low 筛选。接受建议和忽略只记录作者决定；重新审核新增记录，旧报告保留。

连续创作增加 reviewing 阶段。passed / needs_review 继续，critical 暂停；作者点击“我已审阅，继续创作”后记录 author_acknowledged 和时间，直接进入下一章，不重写前章。最后一章有严重问题时也需要确认。审核失败保留正文和版本，显式重试只重做审核。

## Schema、Prompt 和指标

13项为人物、世界、能力、时间线、关系、伏笔、大纲执行、剧情推进、重复、水文、上一章衔接、Bible、Memory。风险指标 repetitionRisk / fillerRisk 越高风险越高，其他单项越高越好。总分由模型综合评估，不简单平均；critical 必须有严重 finding，不仅由分数决定。

finding 包含 category、severity、title、description、evidence、relatedMemoryId、relatedCharacterId、relatedChapterId、suggestion。每条证据包括 source、sourceId、excerpt。服务端检查引用属于输入资料、引文实际存在，高风险问题须引用本章。结构及逐字证据校验不能证明模型语义判断正确，作者仍需审阅。

Prompt 要求不因文学偏好制造事实冲突，缺乏证据时不判冲突，不要求每章都推进伏笔，大纲执行根据实际事件判断而非关键词。审核不能把新事实自动升级为 Bible。

## Context 与性能

输入含 Bible、已确认章纲、人物状态与基础人设、重要 active Memory、世界资料、时间线、未回收伏笔、本章、上一章及最近5章摘要。只发送本章和上一章正文，不发送全书正文。

当前最多60个人物、80条世界资料、100条重要 active Memory、40条时间线、5章摘要，总输入限制180 KB；超限在调用前拒绝。没有向量检索。提示词区分本章分析新投影与既有事实，但目前没有完整的历史人物状态快照，长篇中较早或未入选的事实可能漏检。

## 数据库、权限和日志

012 为新增迁移，不修改001–011。chapter_reviews 关联小说、章节、可选版本、用户、连续任务和日志，保存结果、模型、prompt版本、tokens、耗时、错误、作者决定、正文 hash 和章节/小说版本号。运行时正文或小说资料版本变化则结果标为 stale。013 允许所有者读取报告的小说版本号，用于中断恢复时核对已保存报告；仍受 RLS 约束，不开放租约列。

RLS 仅允许所有者读取，写入通过验证 session、小说、章节、版本归属的窄 RPC。租约列不允许 REST 读取。应用使用公开 Supabase key 加用户会话，不使用 service role。generation_type=chapter_review 的日志关联 chapter_id、chapter_version_id 和 generation_run_id，不保存密钥或完整提示词。

同章同正文自动审核唯一；刷新和重复提交复用。手动重新审核新增历史。自动失败最多重试一次；两次尝试各有日志，审核记录保存尝试次数。重试须持有不可读租约，轮询不会无限收费。

| 接口 | 功能 |
| --- | --- |
| GET `/api/ai/chapters/review` | 当前章节最近30次报告，数据库保留全部历史 |
| POST `/api/ai/chapters/review` | 手动审核、接受/忽略建议、确认 |
| POST `/api/ai/generation-runs/[id]/continue` | 作者确认严重问题后继续 |

普通 AI 操作共用每账号每小时6次上限；明确确认的连续任务使用36次上限，覆盖10章正常的30次调用和有限重试。测试不清空额度记录。确认弹窗展示正文、记忆、审核三类调用；模型来自服务器环境配置。

014 统一审核重试的限额：单章下一章任务仍为6次，只有 continuous 模式使用36次。

## 失败与恢复

格式、schema、证据、超时和网络异常最多自动重试一次。审核失败不会删除正文、版本和记忆；手动重新审核保留失败历史。连续任务可刷新恢复，审核重试续租，重复领取不会再调用模型。

真实验收发现模型会在截取长对话的一句后补上结束引号。记忆与审核共用证据校验：仅当去掉最外层成对引号后的全部文字确实连续存在于原文时，去掉多余引号；内部文字、标点、拼接或省略均不放宽。审核的 chapter 来源仅匹配正文，不能用章纲冒充正文。错误日志只记录校验路径，不记录私有原文。

记忆分析进一步使用服务端原文片段目录：每片段最多480字符，模型的 evidence 字段由动态 JSON Schema 限定为目录编号；服务器将编号还原为原文后再验证并写入数据库。未知编号拒绝，不让模型重抄引文。该机制保证引用来自原文，不能单独证明模型对引文的语义解释正确。完整输入和 Schema 同样受180 KB限制。

若显式重试已保存新报告，但工作进程尚未推进任务就中断，恢复时复用同一任务、正文 hash、章节及小说版本匹配的成功报告，不再次付费调用。单元测试覆盖该边界。

Next after 执行后台步骤，当前不是常驻队列。浏览器重开后可点击继续任务。单章确认的记忆加审核最多900秒；独立审核/连续审核步骤最多600秒。未来部署需确认平台函数时限，本阶段没有生产部署。

正常样本最初获得80分：审核发现21:01时登记簿出现21:10记录，以及未落实章纲的调查方法。修正这两处测试文本后获得94分。同章两次报告和版本均保留，用于历史与重新审核验收。没有为获得通过而降低审核阈值。

真实连续三章已完成，审核分别为84分 needs_review、90分 passed、90分 passed；每章都有唯一 AI 正文版本、成功记忆任务、摘要和报告。84分报告不会触发 Critical 暂停。严重冲突专项则实际暂停，浏览器点击作者继续后进入下一章，确认时间落库，原章正文与版本数量不变。

本次留存的真实 DeepSeek 调用共23次：17次成功、6次失败；输入168411 tokens，输出98851 tokens。包含排查和修复前的无效引文/JSON尝试，未清除失败或限额记录。这不是一次正常三章任务的预计费用；正常三章需要正文、记忆、审核共9次调用，重试另计。故意制造冲突的正文夹具不计入真实模型调用数。

### 已知限制

- 审核是模型判断，原文证据存在不等于语义推理一定正确；作者需最终审阅。当前样本不构成准确率承诺。
- 使用有界资料选择，无 RAG、向量检索或完整历史人物状态快照；长篇较早事实可能漏检。
- Next after 不是持久后台队列；服务进程退出后的后续步骤需重开页面继续，部署函数时限仍需后续验证。
- 当前作品读取仍含完整聚合，百万字实际负载、按章读取和分页尚待后续阶段。
- 审核不自动修复正文，作者接受建议只记录决定。会员、支付、广告和生产部署均不属于本阶段。
